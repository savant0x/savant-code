## Lessons Learned

- Run the scoped preview before mutation; it makes package scope and binary
  expectations explicit.
- Automation commits the entire dirty worktree by design, so the worktree must
  be intentionally release-ready before starting.
- A failed gate before `TAG`/`GIT_PUSH`/`GITHUB_RELEASE`/npm is safely rerunnable
  after fixing the reported issue; verify the receipt before deciding between a
  fresh run and resume.
- Release notes should be written for both pre-release preparation and the final
  published page; otherwise accurate implementation can still produce stale
  public wording.
