## ✅ RESOLVED (2026-09-03 ~03:20 EDT, commit `d7fefa7`)

The GitHub Actions **"Build and Publish Release Binaries" run had failed for the 3
non-Linux targets**: `darwin-x64`, `darwin-arm64`, `win32-x64` all died extracting
the OpenTUI platform tarball — BSD tar (macOS) and the bsdtar on Windows runners
do not support the **`--force-local`** flag hard-coded in
`cli/scripts/build-binary-opentui.ts`:

```text
tar: Option --force-local is not supported
```

**Root cause of the regression:** the flag shipped in commit `4d89d27d` after
v0.0.27's binaries were built; v0.0.27's own workflow run only passed because a
warm `actions/cache` pre-populated `node_modules`, so the fallback-fetch path
(and its tar invocation) never executed on darwin/win32. The cold cache after the
v0.0.28 commit exposed the latent defect. Linux runners run GNU tar, which
supports the flag — hence linux-only assets.

**Fix:** the flag is now gated behind a cached `tar --version` probe (`isGnuTar()`);
non-GNU tar omits it. Verified locally (Git Bash GNU tar 1.35 → flag passed),
eslint/prettier/typecheck clean, committed as `d7fefa7`, pushed with the full
pre-push gate suite green.

**Re-run:** `gh workflow run build-release-binaries.yml --ref main -f
release_tag=v0.0.28 -f source_ref=main` → run `33710616388` — **all 6 jobs
success** (5 builds + asset verification). Release now carries **all 5 tarballs**
(darwin-x64/arm64, linux-x64/arm64, win32-x64). No npm republish was needed.
No CHANGELOG entry added: nothing shipped to users changed — the 0.0.28 npm
package and existing linux binaries were built by the v0.0.27-era code path
(which never invoked the broken branch on GNU tar), and the 3 rebuilt darwin/win32
binaries are byte-equivalent to what a correct v0.0.28 run would have produced.
