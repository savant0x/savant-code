1. **The rejection names the field.** `summarizeSchemaIssue` reads the issue `path` + `code` + `expected` and
   never the payload (`TypeValidationError.message` embeds the received value, so it is not read at all).
   Carried as `NativeToolCallError.schemaIssue` (guarded like `finishReason`) into the message factory, which
   adds ` The arguments failed the tool schema at: followups[0].prompt — invalid_type (expected string).`
   Bounded to 120 characters, exclusive with the truncation clause.

   for one stream; `handleStreamErrorChunk` takes `isDuplicate` and skips the `TOOL_CALL_ERROR` push for a
   repeat. Class, tool name, `captureChunk` and the strike ladder are unchanged, and **no ledger row is
   dropped** — shrinking capture volume is a capture-policy decision that belongs to `FID-2026-1012-024`.
