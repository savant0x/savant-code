# v0.0.23 — Comprehensive Live Update and Regression Test

**Version:** 1.0.0
**Date:** 2026-08-11
**Status:** Active live-test prompt
**Target:** pending, unreleased `0.0.23` working-tree update
**Purpose:** Exercise the user-visible and operator-visible behavior delivered by the current update, not merely the design-system feature or the unit suites.

This is a live behavioral and release-readiness test. It complements unit tests,
source review, and independent audit; it does not replace them. Execute the
applicable tests against the real CLI, SDK/headless paths, release diagnostics,
packaging wrappers, and offline browser artifact in disposable locations.

Do not publish, push, commit, tag, deploy, use real credentials, contact remote
release services, modify production projects, or modify source files during this
run. The pending release is intentionally not certified by this prompt.

## 1. Execution contract

Point the current orchestrator at this file and instruct it:

> Read this complete prompt, execute every applicable test phase, record exact
> outputs, exit codes, timings, and evidence, continue after failures, and write
> the final report to `dev/scratchpad/v0.0.23-comprehensive-live-test-report.md`.

The testing agent must:

1. Read this file from start to end before executing a test.
2. Create one todo per phase and update it as phases finish.
3. Record every test as `PASS`, `FAIL`, `NEEDS-REVIEW`, or `SKIP`.
4. Prefer observable behavior over source claims. A source-only check must be
   labeled `STATIC`, and a live behavior must include its command/output or
   captured UI/file artifact.
5. Continue after individual failures. Capture exact error text, exit status,
   duration, and the last observable state.
6. Use no real provider keys or credentials. If a provider is required, use an
   already available local/offline backend or mark the model-dependent test
   `NEEDS-REVIEW` with the environmental reason.
7. Use a disposable project under `dev/scratchpad/` or the OS temp directory.
   Never point project-scoped tests at the repository's real project state.
8. Run user-scope tests only after proving isolation of `HOME`, `USERPROFILE`,
   and platform-specific config variables. Otherwise mark them `SKIP`.
9. Keep all fixtures, exports, manifests, reports, and temporary settings inside
   the disposable boundary until cleanup.
10. Redact credentials, personal paths, environment values, tokens, and unrelated
    conversation text in the final report.
11. Leave the repository's pre-test working-tree state unchanged. Record that
    state; do not call it clean unless it was clean before testing.
12. Remove all disposable artifacts except the final report after evidence is
    captured. Confirm restoration instead of inferring it from a command tail.

### Findings classification

Classify every issue as one of:

- `PRODUCT-BLOCKER` — unsafe, unusable, or incorrect intended behavior;
- `REGRESSION` — prior supported behavior is broken;
- `SECURITY/PRIVACY` — boundary, credential, path, provenance, or data leak;
- `GOVERNANCE` — FID, protocol, evidence, attribution, or tracking defect;
- `UX-FRICTION` — confusing, noisy, or unnecessarily difficult behavior;
- `PERFORMANCE-REGRESSION` — reproducible degradation against matched baseline;
- `PACKAGING` — shipped artifact or wrapper mismatch;
- `AGENT-FEEDBACK` — grounding, explanation, or correction problem;
- `ENVIRONMENT` — provider, OS, terminal, network, or tool limitation;
- `NEEDS-REVIEW` — evidence incomplete or not reproducible.

## 19. Final evaluator guidance

The changelog is the coverage index, not a substitute for evidence. Test each
current-update domain separately and preserve historical boundaries. A green unit
suite does not prove that the CLI boots, a user can recover a draft, an offline
export works in Chrome, release diagnostics are reversible, or an agent can
self-correct a design-contract block. Conversely, a provider timeout, dirty tree,
missing optional browser, or environment timeout does not prove a product defect.
Report those as bounded limitations and keep the final verdict honest.
