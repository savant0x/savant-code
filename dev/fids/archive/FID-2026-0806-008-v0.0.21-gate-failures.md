## Summary

The v0.0.21 A-Z audit run (transcript, `az-test-v0.0.21-release.md`) surfaced
three release-gate failures that must be fixed before the repo is pushable:
(1) the SDK build breaks on a missing `exec` in the SDK's `bun:sqlite` type
stub, (2) ESLint fails on import ordering in an SDK example, and (3) markdownlint
fails on 109 MD013 (line-length) violations across a dated design doc, the
scratchpad audit report, and three Nova inbox files. This FID converges the fix
design; the fixes themselves are small and will be applied in the implementation
phase (Forge), then re-verified.

## Detailed Description

### Problem 1 — SDK build fails (T1.6)

`cd sdk && bun run build` fails at the declaration-bundling step:

```text
../packages/knowledge-graph/src/store.ts(70,20): error TS2345: Argument of
type 'Database' is not assignable to parameter of type
'{ exec(sql: string): unknown; prepare(sql: string): { run(...): unknown } }'.
  Property 'exec' is missing in type 'Database' but required in type
  '{ exec(sql: string): unknown; prepare(sql: string): ... }'.
```

### Problem 2 — ESLint warnings (T1.2)

`bun x eslint . --max-warnings 0` fails with 2 warnings in
`sdk/examples/readme-example-2.ts`: an empty line inside the import group
(`1:1`) and `@savant-code/sdk` imported after `zod/v4` (`4:1`, `import/order`).
One warning is auto-fixable.

### Problem 3 — markdownlint MD013 (T1.3)

`bun run lint:md` fails on 109 line-length violations:
`docs/design/AI-Playbook-Integration-Plan.md` (72), `dev/scratchpad/az-test-v0.0.21-results.md`
(22), and the three active Nova inbox files (3 + 10 + 2).

### Expected Behavior

- `cd sdk && bun run build && bun run verify` exits 0.
- `bun x eslint . --max-warnings 0` exits 0.
- `bun run lint:md` exits 0.

### Root Cause

1. `sdk/types/bun-sqlite.d.ts` — the SDK's minimal `bun:sqlite` type stub
   (added for dts-bundle-generator, FID-2026-0804-004) declares
   `Database { constructor; prepare; query; close }` but omits `exec`, which the
   real `bun:sqlite` API has and which `packages/knowledge-graph/src/schema.ts`
   requires structurally (`applyGraphSchema(db: { exec; prepare })`).
2. `sdk/examples/readme-example-2.ts:1-7` — import order violates the configured
   `import/order` rule (`eslint.config.js:115`).
3. Markdownlint policy gaps: dated design docs, ephemeral scratchpad reports,
   and the third-party Nova channel are not exempt, even though the repo already
   exempts analogous paths (`docs/launch/**`, `docs/reports/**`,
   `dev/fids/archive/**`, `dev/test-prompts/archive/**`, `dev/nova/reports/**`).

### Evidence

## Proposed Solution

### Approach

Minimal, precedent-consistent fixes. Do not wrap 72 lines of a dated design
report; exempt it like every other dated doc. Do not edit third-party Nova
channel files; exempt the channel like `dev/nova/reports/**`.

### Steps

1. **SDK stub** — add `exec(sql: string): void` to the `Database` class in
   `sdk/types/bun-sqlite.d.ts` (matches the real `bun:sqlite` API; the stub's
   comment already promises a "minimal bun:sqlite type surface").
2. **ESLint** — run `bun x eslint --fix sdk/examples/readme-example-2.ts`
   (fixes the empty line + import order); hand-adjust if the directive comment
   placement needs care. Re-run `eslint . --max-warnings 0`.
3. **Markdownlint ignore policy** — append to `.markdownlintignore`:
   - `dev/scratchpad/**` (ephemeral working area; precedent: archive dirs)
   - `dev/nova/inbox/**` + `dev/nova/outbox/**` (third-party audit channel;
     precedent: `dev/nova/reports/**`)
   - `docs/design/AI-Playbook-Integration-Plan.md` (dated design report;
     precedent: per-file entries like `docs/Launch Plan Review and Optimization.md`)
4. **Re-verify** — `cd sdk && bun run build && bun run verify` (exit 0);
   `bun x eslint . --max-warnings 0` (clean); `bun run lint:md` (0 errors).

## Lessons Learned

Type stubs and real APIs drift silently — a declaration-bundled stub must be
checked against the runtime surface. Lint gates need explicit policy for
ephemeral and third-party paths, or every audit generates new red herrings.
