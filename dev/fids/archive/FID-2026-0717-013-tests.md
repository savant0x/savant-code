### Missed Questions

1. **What test framework?** — Bun's built-in test runner. Already used in `packages/agent-runtime/src/__tests__/`. Import from `bun:test`.
2. **Should tests run in CI?** — Yes. Add `test` script to root `package.json` and include in `bun run ci`.
3. **How to test database without a real DB?** — Use in-memory SQLite (`:memory:`). The database module accepts a path — pass `:memory:` for tests.
4. **How to test FSM transitions without a full agent run?** — Import `handleTransitionPhase` directly. Mock `agentState` and `toolCall`. Call the handler and check output.
5. **How to test file snapshots without writing to disk?** — Use a temp directory. Create test files, run snapshot capture, modify files, run restore, verify content.
6. **How to test depth limits without spawning real agents?** — Call `createAgentState()` with a mock `parentAgentState` that has deep `ancestorRunIds`. Check that it throws.
7. **How many test cases per module?** — Keep it minimal: 3-5 per module. Focus on happy path + edge cases + error cases.
8. **Should tests be in the same directory as source or in `__tests__/`?** — Follow existing convention: `__tests__/` subdirectory.
9. **What about integration tests?** — Defer. Unit tests first. Integration tests require full runtime setup.
10. **Should the test script be `bun test` or `bun run test`?** — `bun test` (Bun's built-in test runner). The `test` script in package.json should call `bun test`.

### SELF-CORRECT Phase

**Finding:** The original plan lists 5 test modules with many test cases. This is a large scope.

**Correction:** Start with 3 modules: FSM transitions, snapshot store, depth limits. These are the most critical and easiest to test. Database and knowledge pipeline tests can follow.

**Finding:** Testing `handleTransitionPhase` requires mocking `agentState` and `toolCall`.

**Correction:** Create a `createMockAgentState()` helper that returns a valid `AgentState` with configurable `fsmPhase`, `runId`, `iterationCount`. Reuse across tests.

**Finding:** Testing snapshot store requires filesystem access.

**Correction:** Use `os.tmpdir()` for test files. Clean up after each test. Standard pattern in the codebase.
