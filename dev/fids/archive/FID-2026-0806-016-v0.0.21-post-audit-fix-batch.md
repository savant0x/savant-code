### Finding 2 — Basher subagent phase-enforcement waste (Nova bug report)

#### Problem

The basher subagent wastes ~500 tokens on a "failure ceremony" when spawned in the
`idle` phase: it tries `run_terminal_command`, fails, analyzes why, explains the
failure in detail, and offers alternatives. The failure is predictable —
`run_terminal_command` is FSM-gated.

#### Expected Behavior

Basher fails fast with a one-line report, or the parent transitions phase before spawning so the command runs first try.

#### Root Cause

`packages/agent-runtime/src/tools/tool-executor/native.ts:170` gates
`run_terminal_command` to `['audit', 'green']` only. The orchestrator system prompt
*already* instructs transitioning before spawning terminal-capable subagents
(`agents/savant/system-prompt.ts:143`), but the basher's own prompt has no fail-fast
self-check, so a spawn from `idle` burns tokens explaining the inevitable block.

#### Evidence

  the ~500-token ceremony)

### Finding 4 — FSM `self_correct` verification deadlock (discovered in the A–Z run)

#### Problem

During the audit run, after writing the results report the agent was in `self_correct`
and needed to run verification (`run_terminal_command`) to clear the Law 3
"unverified file(s)" gate — but the runtime blocks `run_terminal_command` in
`self_correct`. Transitions out of `self_correct` are `green|complete|idle`; `green`
is additionally FID-gated (no open FIDs in a read-only audit), so the agent deadlocked
and could only force `complete`.

#### Expected Behavior

The documented contract says `self_correct` **may verify inline** —
`common/src/constants/agents.ts:202` lists `run_terminal_command (phase-gated)` for
self_correct, and ECHO.md SELF-CORRECT row implies verification before `complete`.
The runtime must match the doc.

#### Root Cause

Runtime/contract mismatch: `native.ts:170` only allows `['audit', 'green']` for
`run_terminal_command`, but the documented phase table grants `self_correct` the tool.

#### Evidence

- `packages/agent-runtime/src/tools/tool-executor/native.ts:170` — `!['audit', 'green'].includes(...)`
- `common/src/constants/agents.ts:202` — self_correct row includes `run_terminal_command (phase-gated)`
- `packages/agent-runtime/src/tools/handlers/tool/transition-phase.ts:29-37` —

### Finding 5 — ADHD-friendly output mode (Nova feature question) — retrofit decision

#### Problem

Nova asks whether to implement an ADHD-friendly output mode (10 rules from
`i-have-adhd`, 17.7k★) and which integration option (A: new mode / B: agent-specific /
C: skill / D: hybrid).

#### Operator guidance (2026-08-06)

> "We are simply taking the idea and perfecting it to our system, not a direct 1:1 port…
> if we don't really need it, say that, if we can retrofit it, say that, the idea is not
> concrete."

#### Honest assessment

The repo **already ships** an opt-in Caveman telegraphic-output mode (P5f,
`protocol.config.yaml caveman.enabled`, applied at the runtime prompt boundary to
Orchestrator/Detective/Scribe — `packages/agent-runtime/src/util/caveman-rules.ts`,
wired at `packages/agent-runtime/src/templates/strings.ts:290`). The 10 ADHD rules
overlap heavily with what Caveman already does: *no preamble / no closers / suppress
tangents / matter-of-fact errors / lead with action* are all Caveman staples. The
truly new, useful rules are:

1. **Number multi-step tasks** (rule 02) — Caveman is fragment style; numbering is additive
2. **Cap lists at 5 items** (rule 09) — small, cheap, works with fragments
3. **End with one concrete next step** (rule 03) — pairs with existing no-preamble style
4. **Specific time estimates** (rule 06) — genuinely new; low value for an agent (no wall-clock grounding), **drop**

Not needed as a new mode (the mode axis is execution scope —
HYBRID/SCAFFOLD/STRICT/ANALYZE — output formatting does not belong there), not needed
as a skill (Caveman config already exists and is opt-in). **The right retrofit is a
small additive enhancement to the existing Caveman rules block** — Option A folded
into the existing system, not a port, not a new surface.

## Lessons Learned

- An audit run exercising the harness is itself the best integration test for the harness —
  the self_correct deadlock was invisible until a read-only audit tried to write its report
  and verify it.
- "Port the idea" is the wrong frame for features like ADHD mode; the right frame is "which
  rules does our system already satisfy, which add value, which don't fit" — then retrofit
  only the value-adds onto the existing surface.
- Zero-tolerance lint gates catch exactly what they should: a one-line comment placement that a human review would miss.
