# FID: v0.0.24 shipped without binaries — phantom `@noble/hashes` dependency + release-pipeline scope defect

**Filename:** `FID-2026-0816-001-v0.0.24-bad-build-phantom-dependency-and-pipeline-scope.md`
**ID:** FID-2026-0816-001
**Severity:** high
**Status:** closed
**Created:** 2026-08-16

---

## Summary

The `v0.0.24` release was pushed live (commit `05f829a`, tag `v0.0.24`, GitHub release,
`npm publish savant-code@0.0.24`) but its platform binaries were **never built**: the
`build-release-binaries.yml` workflow failed on all 5 platforms at the `Build binary`
step with `error: Could not resolve: "@noble/hashes/sha512"` at
`common/src/crypto/keys.ts:2:24`. Root cause: the ZTAP provenance work imports
`@noble/hashes/sha512` but `@noble/hashes` was **never declared** in
`common/package.json` and is absent from `bun.lock`. Every local gate (typecheck ×11,
test ×11, eslint, prettier, `release:public:diagnose` 13/13) passed against a
**phantom hoist** — the import resolved from `C:\Users\spenc\node_modules\@noble\hashes`
(a node_modules *outside the repo*), so only the CI compile could see the missing
dependency. The npm `savant-code` launcher downloads its platform binary from the
GitHub release; with zero assets, installed `0.0.24` is broken.

Two additional defects are folded in because they caused and masked the failure:

- **Release-pipeline scope defect:** `PUBLIC_PACKAGES` hard-codes `@savant-code/sdk`
  first, but the `@savant-code` npm scope does not exist and the SDK is never
  published (operator-confirmed). The 0.0.24 run died at the SDK publish; the
  `--resume` path is fail-closed against a differently-scoped gate manifest, and the
  CLI was published by a manual `npm publish` outside the pipeline (process error:
  the first run should have been scoped with `SAVANT_CODE_RELEASE_PACKAGES=savant-code`).
- **No recurrence guard:** the release gate manifest runs 11 root gates but never the
  CLI binary build — the exact step that failed in CI — so a phantom/undeclared
  dependency can pass every local gate and only break the shipped binary.

Operator decision: `v0.0.24` is live on npm and cannot be republished; the fix ships
as **`v0.0.25`** with the dependency declared, the pipeline scoped to the main package,
and a binary-build gate added so this class can never slip a release again.

## Detailed Description — the audit surface (RED)

### D-01 (P0) — Phantom `@noble/hashes` dependency

- `common/src/crypto/keys.ts:2` — `import { sha512 } from '@noble/hashes/sha512'`
  (ZTAP provenance, FID-2026-0813-001..010).
- `common/package.json:44` — declares `@noble/ed25519` only; **no `@noble/hashes`**.
- `bun.lock` — exactly 2 `noble` references (`:98`, `:469`), both `@noble/ed25519`;
  `@noble/hashes` absent. A frozen install therefore never installs it.
- Local resolution rides a phantom: `bun -e "import.meta.resolve('@noble/hashes/sha512')"`
  → `file:///C:/Users/spenc/node_modules/@noble/hashes/esm/sha512.js` (outside the
  repo; `@noble/hashes@1.8.0` left over from another project). That is why all local
  gates were green.
- CI failure (workflow run `31925785658`, job `Build linux-x64`, step `Build binary`):
  `error: Could not resolve: "@noble/hashes/sha512". Maybe you need to "bun install"?
  at /home/runner/work/savant-code/savant-code/common/src/crypto/keys.ts:2:24`.
- Outcome: zero binary tarballs on the `v0.0.24` GitHub release; the npm launcher
  (`savant-code@0.0.24`, live on the registry) cannot fetch a platform binary → broken installs.

### D-02 (P0) — Release-pipeline scope defect (SDK hard-coded first)

- `scripts/public-release.ts:110-111` — `PUBLIC_PACKAGES` = `[@savant-code/sdk, savant-code]`,
  SDK first. The `@savant-code` npm scope does not exist (`npm view @savant-code/sdk` → E404)
  and the SDK is never published (operator-confirmed; 0.0.21/0.0.23 releases only ever
  published the CLI).
- The 0.0.24 run failed at `NPM_PUBLISH_SDK`; `--resume` with
  `SAVANT_CODE_RELEASE_PACKAGES=savant-code` is refused because
  `validateResumeReceipt` recomputes the gate manifest (`buildGateManifest` includes
  the per-package npm-pack dry runs) and the recorded manifest was bound to both packages.
- Process error (recorded honestly): the first release run should have been scoped
  `SAVANT_CODE_RELEASE_PACKAGES=savant-code` — the pipeline's documented mechanism for
  "main package only". It was not; the CLI was then published with a manual
  `npm publish` outside the pipeline, leaving the temp receipt stale.

### D-03 (P1) — No gate catches phantom/undeclared dependency resolution

- `scripts/validation-manifest.ts:93` `repositoryValidationGates` = 11 gates
  (lockfile, build:sdk, typecheck, test, eslint, repository-validation,
  provider-reference, hygiene, protocol-bundle, markdownlint, prettier) + the two
  npm-pack dry runs in `buildGateManifest` (`scripts/public-release.ts:429`).
- The CLI binary build (`cli/scripts/build-binary.ts` — the exact step that failed in
  CI) is **not** part of the gate manifest, so the resolution failure was invisible to
  every pre-push and release gate. `/cli/bin/` is gitignored (`.gitignore:44`), so the
  compile can run as a gate without dirtying the worktree fingerprint.

### D-04 (P1) — Live-release state

- `v0.0.24` is committed/pushed/tagged/released and `savant-code@0.0.24` is on npm,
  but the GitHub release carries zero binary assets and npm cannot republish `0.0.24`.
- Operator decision: bump to **`v0.0.25`** with the fix. Optional remediation for
  users who already installed `0.0.24`: dispatch `build-release-binaries.yml` for
  `v0.0.24` with `source_ref` = the fixed commit to backfill the tarballs.

## Proposed Solution (GREEN) — the fix plan, in dependency order

**G-01 — Declare `@noble/hashes`.** Add `"@noble/hashes": "^1.8.0"` to
`common/package.json` dependencies (alphabetical: after `@noble/ed25519`; `1.8.0` is
the version proven working locally). Run `bun install` to add it to `bun.lock`.
**Verify:** `import.meta.resolve('@noble/hashes/sha512')` resolves to the repo's own
`node_modules`, never `C:\Users\spenc\node_modules`.

**G-02 — Pipeline default = main package only.** Add `defaultPublish: boolean` to
`PackageTarget` (`scripts/public-release.ts:33`); `@savant-code/sdk` →
`defaultPublish: false` (catalog-only, opt-in via `SAVANT_CODE_RELEASE_PACKAGES`),
`savant-code` → `defaultPublish: true`. `configuredReleasePackages()` defaults to the
`defaultPublish !== false` subset; the env-scoped fail-closed path is unchanged.
Update the affected assertions in `scripts/public-release.test.ts` (public-package
order test, mutation-plan test, gate-manifest labels test, default-scope test).

**G-03 — Phantom-resolution guard.** Add a `cli-binary-build` gate to
`repositoryValidationGates` (`scripts/validation-manifest.ts`): `bun run
scripts/build-binary.ts savant-code 0.0.0-dev` with `cwd = path.join(root, 'cli')` —
the exact CI-failing step becomes a fail-closed release gate. `bun` is on
`ALLOWED_RELEASE_COMMANDS` (`scripts/public-release.ts:857`) and `/cli/bin/` is
gitignored, so the gate is safe for the worktree-fingerprint check. This retires the
entire phantom-dependency class for future releases.

**G-04 — Bump to 0.0.25.** `bun run scripts/bump-version.ts 0.0.25 --docs` (updates
`VERSION`, the 16 synchronized manifests, `protocol.config.yaml`, `bun.lock`, and the
README/docs/CHANGELOG surfaces), then write the `## 0.0.25` CHANGELOG section above
`0.0.24` documenting this hotfix (so `extractChangelogSection('0.0.25')` captures it).

**G-05 — Verification.** Full gate sweep (typecheck ×11, test ×11, eslint, lint:md,
prettier, validate:repository, version:check, quality:report, hygiene, all
generate:* checks) + `release:public:diagnose` (now 14 gates incl. the binary build)
green; in-repo `@noble/hashes` resolution proven.

**G-06 — Release (operator-go, not auto-executed).** Run `release:public` for
`0.0.25` (main-package default after G-02), the binary workflow auto-triggers on
`release: published`, verify all 5 tarballs. Optionally dispatch the `v0.0.24`
backfill. No push/tag/publish without explicit operator approval.
