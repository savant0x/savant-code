03 / The engineering contract

Fifteen laws.
One discipline.

Four core process laws and eleven code-quality laws. Expand a law to see the intent. These are protocol requirements; runtime enforcement depends on mode and implementation.

01Read before touch

Read and understand the complete file before changing it. Existing patterns and sibling code matter.

02Present before act

Document the intended change and its impact before implementation, with approval appropriate to the automation level.

03Verify before proceeding

Run the project's declared build and test gates. A claim that code works is not verification evidence.

04Prove call-graph reachability

Check production entry points and callers. Code that compiles but is never called is not a wired feature.

05No placeholders

Deliver implemented behavior rather than pseudocode, unfinished TODOs, or placeholder paths.

06Preserve type safety

Use explicit domain types and safe language patterns instead of bypassing checks to silence errors.

07Search before creating

Look for an existing implementation before adding a function, module, or duplicate abstraction.

08Log intent

Record the planned change in the session trail before code is written.

09Document for production

Explain contracts, operation, and maintenance so the implementation can outlive its original session.

10Keep tracking current

Update the work register and implementation records as features are verified.

11Follow established patterns

Use the project's existing conventions rather than creating a parallel source of truth.

12Protect sensitive data

Keep credentials and sensitive content out of logs, errors, and documentation.

13Share universal logic

Combine overlapping behavior into cohesive utilities instead of multiplying special-case copies.

14Handle failure paths

Propagate or explicitly handle fallible operations. A silent error is not a successful result.

15Keep the build clean

Re-run verification after changes and resolve errors and warnings before claiming completion.

05 / Under the neon

A shared engine.
Multiple surfaces.

CLI, SDK, and desktop surfaces share a runtime. Explore the systems that turn a conversation into a traceable engineering workflow.

01 / CODE UNIVERSESee the structure, not just the files

A SQLite-backed knowledge graph maps imports, calls, and inheritance with tree-sitter. Detective and Scout can query blast radius; /graph-export creates an offline interactive repository snapshot.

02 / DURABLE EXECUTIONGoals that keep their place

/goal tracks active, paused, blocked, and complete states with token, turn, and time budgets. Auto Drive adds clarify → plan → approve → execute, with its own management commands.

03 / ZERO-TRUST PROVENANCEReceipts, not reassurance

ZTAP records hash-only, per-role Ed25519-signed write receipts and verdict bindings. It provides evidence of recorded mechanical process and integrity—not proof of independent LLM reasoning. Modes: off, record, enforce.

04 / CHECKPOINT & REWINDGo back without rewriting history

Turn checkpoints preserve pre-edit file content and conversation boundaries. Restore code, conversation, both, or fork a session. Terminal side effects cannot be rewound.

05 / EXTENSIBILITYBring your own tools

Custom skills, MCP discovery, connector tools, and lifecycle hooks extend the runtime. Agent-authored skills enter quarantine; trust and release remain operator decisions.
