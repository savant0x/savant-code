Architectural Evaluation: Dual-Mode Model Selection and Asynchronous Media Execution in Terminal-Native Coding AssistantsThe integration of generative media synthesis into an interactive software engineering harness introduces structural friction between two fundamentally distinct computational paradigms. Conversational coding harnesses operate on high-cadence, multi-turn, low-latency token streams coupled to deterministic tool executions and local filesystem mutations. In contrast, media generation—particularly high-definition video synthesis—is characterized by multi-minute inference latencies, decoupled asynchronous job queues, non-conversational single-turn prompt conditioning, high per-call financial costs, and ephemeral binary artifacts.This investigation evaluates whether a user-facing mode switch, toggling the model picker between a text/coding mode and an image/video media mode, represents the soundest architectural abstraction for resolving these tensions within the Savant-Code monorepo (release v0.0.36, Bun runtime, React/OpenTUI terminal interface, governed by the ECHO Protocol v0.2.0).Evaluation of Model Selection Primitives and Direct RecommendationThe working hypothesis proposing a top-level mode switch that swaps the primary model picker between coding models and media generation models is fundamentally flawed. The primary model in an engineering agent harness is not an interchangeable commodity across modalities; it constitutes the conversational reasoning engine that parses user intent, formulates architectural plans, executes shell commands, performs static analysis, inspects diffs, and orchestrates specialized tools. Swapping the primary picker to a specialized image or video generation model instantly invalidates the conversational loop. Video and image models cannot parse repository directory structures, cannot evaluate build diagnostics, cannot satisfy typed tool-calling contracts, and cannot engage in multi-turn error correction loops.Comparative Assessment of Architectural AlternativesSelection PatternArchitectural PremisePrimary Mechanical Failure ModeViability Verdict(a) Mode SwitchGlobal setting swaps the primary picker between text and media models.Orchestration Lockout: Switching to media mode breaks conversational coding; switching to text mode blinds the agent to media generation tools during compound tasks.Rejected(b) Filter FacetsSingle flat picker with modality checkboxes (text/image/video).Semantic Incoherence: Allows operators to select a video model as the primary chat engine, causing instant runtime crashes on subsequent conversational turns.Rejected(c) Separate SurfacesCompletely isolated CLIs or execution binaries (e.g., savant media).Agent Isolation: Prevents the coding agent from programmatically generating assets (e.g., landing page hero graphics, CSS assets) during refactoring workflows.Rejected(d) Capability-DrivenZero user picker; agent dynamically selects models based on inferred task need.Spend & Control Hazard: Strips operator control over expensive model invocations; high risk of unexpected bills and inability to benchmark specific models.Rejected(e) Decoupled Hybrid (Recommended)Primary picker selects conversational reasoning models; media models are configured as tool backends or invoked via dedicated slash-commands.Configuration Desynchronization: Requires clear fallback semantics if no media provider API key is configured when the tool is called.RecommendedThe Mid-Task Transition FailureThe conceptual collapse of the top-level mode switch manifests during compound developer tasks. Consider an operator instructing the harness to construct a landing page for an authentication service, implement the styling layout, generate an isometric graphic depicting a cryptographic vault, and wire that graphic into the frontend asset pipeline.If the system relies on an exclusive mode switch, execution immediately fractures. Under text mode, the agent plans the component hierarchy, creates the layout files, and modifies stylesheets. When the agent identifies the requirement to produce the cryptographic vault graphic, the catalog filter in cli/src/utils/openrouter-models/catalog-filter.ts has excluded all non-text models from the active roster. The agent has neither a tool schema nor a runtime binding to invoke an image model. Consequently, the agent must either halt with an unhandled exception or force the operator to exit text mode manually, switch to media mode, generate the asset via an isolated prompt, copy the resulting file path, switch back to text mode, and resume the task.Conversely, if the operator toggles the global mode switch to media mode prior to issuing the prompt, the primary model driving the session becomes an image or video model. Because media models lack conversational turn-taking, instruction-following depth, and tool execution capabilities, the session cannot inspect files, edit code, or run build verification commands, causing the entire session to fail on turn zero.The Recommended Architecture: Decoupled Hybrid Model SelectionThe harness must establish a clean separation between conversational reasoning engines and asset generation pipelines:The primary model picker must be restricted to conversational reasoning models whose output modalities include text and which satisfy the coding harness criteria in catalog-filter.ts. This ensures the conversational driver possesses the capacity to plan, write code, invoke tools, and interpret feedback.Image and video models discovered during automated catalog scrapes are routed into a secondary execution registry. They are exposed to the conversational engine as an internal agent tool (generate_media), allowing the reasoning model to invoke media generation dynamically during software development tasks.For direct, human-driven generation outside an agent planning loop, the interface provides dedicated interactive sub-commands, such as /image or /video. These commands launch a scoped, ephemeral model picker displaying only media-capable models, executing directly through the underlying asynchronous generation pipeline without mutating the primary conversational session state.Critique of the Maintainer's HypothesisThe working hypothesis correctly observes that text and media models have structurally divergent execution shapes that must not be peer-selectable in a single flat picker. However, resolving this divergence through a top-level user mode switch misidentifies the role of the primary model in an engineering harness. In developer-facing agent systems, the user does not converse with an image or video model. The conversational engine is always a text-capable reasoning LLM, while media models operate as specialized peripheral tools.The missing architectural primitive in the existing codebase is not a modal picker toggle, but an asynchronous submit-poll-fetch execution engine capable of managing long-running generation jobs without freezing the process.This recommendation would only change if frontier AI providers release unified omni-models that combine state-of-the-art coding and agentic reasoning with native, interleaved image and video synthesis within the exact same Server-Sent Events (SSE) token stream.
