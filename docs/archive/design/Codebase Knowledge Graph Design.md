# **Strategic Architecture and Implementation Plan: Codebase Knowledge Graph Integration for Savant Code**

The evolution of artificial intelligence coding assistants has reached a critical context ceiling. While foundational
large language models exhibit profound generative capabilities, their effectiveness degrades sharply when tasked with
navigating enterprise-scale codebases. Traditional retrieval-augmented generation methodologies, which rely on semantic
vector search or rudimentary grep utilities, frequently fail to capture the structural reality of a software system.
They provide isolated fragments of code without illuminating the complex web of dependencies, execution paths, and
business logic that bind those fragments together.
The introduction of deterministic, queryable knowledge graphs represents a paradigm shift in how AI agents perceive
software architecture. By supplying agents with a mathematically rigorous map of a repository—augmented with semantic
domain descriptions—the probability of hallucinated implementations and architectural regressions plummets. This report
delivers an exhaustive architectural evaluation of current knowledge graph implementations, subjects the underlying
concepts to a rigorous perfection and optimization loop, and defines a comprehensive, production-ready specification for
a proprietary knowledge graph feature integrated natively into the Savant Code ecosystem.

## **1\. Architecture Analysis of Understand-Anything**

The open-source project Understand-Anything, developed by Egonex-AI, has garnered significant attention (exceeding
77,000 stars) for its ambitious approach to transforming raw codebases into interactive, queryable visual graphs1. A
deep architectural forensic analysis reveals a mix of pioneering conceptual frameworks and fatal execution flaws that
must inform the subsequent Savant Code design.

### **1.1 Pipeline Mechanics and Structural Extraction**

Understand-Anything operates through a multi-agent, sequential execution pipeline that traverses the target repository
to extract structural and semantic data. The architecture relies on specific, compartmentalized scripts to construct the
final artifact3. The primary mechanism involves scanning the file system, parsing syntax, mapping relationships, and
clustering domains before passing the data to a language model for summarization.

| Pipeline Phase | Core Script | Technical Function |
| :---- | :---- | :---- |
| **Project Scanning** | scan-project.mjs | Executes a mechanical enumeration of the repository, honoring .understandignore and .gitignore parameters, to categorize files, count lines, and assess basic algorithmic complexity3. |
| **Structural Extraction** | extract-structure.mjs | Leverages the Tree-sitter parsing library to generate an Abstract Syntax Tree (AST), identifying core constructs such as functions, classes, and fundamental components across multiple programming languages4. |
| **Dependency Mapping** | extract-import-map.mjs | Maps import and export relationships across supported languages, generating the foundational directed edges of the graph to represent dependencies3. |
| **Community Detection** | compute-batches.mjs | Utilizes the Louvain community detection algorithm to mathematically cluster densely connected nodes into logical domains, subsystems, or execution flows4. |
| **Graph Consolidation** | merge-batch.mjs | Merges the deterministic structural data with semantic overlays generated by the language model into the final master graph artifact4. |

The culmination of this pipeline is a highly structured JSON artifact typically stored in a hidden .ua/ directory (or
the legacy .understand-anything/ directory)7.

### **1.2 The Node and Edge Schema**

The fundamental value proposition of Understand-Anything resides in its exhaustive schema definition. Rather than
treating all code uniformly, the schema segregates data into logical hierarchies, creating a rich tapestry of
relationships that map directly to real-world business logic7.
The schema is divided into the following primary object classes:

* **Project Metadata:** This top-level object stores the repository name, description, active languages, frameworks,
* analysis timestamps, and the specific Git commit hash utilized during the build process, providing critical version
* control context7.
* **Code Nodes:** Entities explicitly extracted from the AST. These are the physical realities of the codebase,
* categorized as file, function, class, module, or concept9.
* **Non-Code Nodes:** Contextual entities that support the application but do not contain executable logic in the
* traditional sense, such as config, document, service, table, endpoint, pipeline, schema, and resource9.
* **Domain/Knowledge Nodes:** Abstract representations of business logic, including domain, flow, step, article, entity,
* and claim. These nodes elevate the graph from a simple dependency map to a true knowledge repository9.
* **Edges:** Directed vectors representing the relationships between nodes. The schema supports highly specific edge
* typing, including imports, calls, depends\_on, configures, documents, deploys, contains\_flow, and cites9.

### **1.3 Architectural Bottlenecks and Systemic Failures**

Despite the brilliance of its schema, Understand-Anything suffers from severe architectural flaws that degrade the user
experience, inflate operational costs, and limit platform interoperability.
The most catastrophic failure point is the system's reliance on cloud-based language models to perform structural
analysis and semantic tagging during the initial build phase. Because the pipeline utilizes multi-agent processing (via
Claude Code's Task tool) to map relationships that could otherwise be determined deterministically, it results in rapid
token exhaustion. Users have documented instances where analyzing mid-sized codebases completely depleted top-tier
subscription token quotas within a five-hour window, rendering the tool financially unviable for continuous use12.
Furthermore, the implementation relies heavily on monolithic, non-incremental processing. While the documentation
implies update capabilities, the practical reality often requires re-parsing massive amounts of unchanged code. The lack
of sub-second, hash-based incremental updates means that keeping the graph current requires disproportionate
computational and financial overhead13. Consequently, users experience "silent staleness," where the graph falls
hundreds of commits behind HEAD because re-triggering the build is too expensive or time-consuming, causing the AI
agents to base their decisions on deprecated architectural logic14.
Platform interoperability is also fundamentally broken due to rigid dependencies. For example, the tool fails completely
in environments like OpenCode because the analysis pipeline relies exclusively on Claude Code's proprietary Task tool
for subagent dispatching. When the Task tool is unavailable, the pipeline simply crashes3.
Finally, the visual exploration of the graph relies on a Vite-based web server spawned locally on port 51733. This
requires Node.js runtimes, dependency installations, and active server management, breaking the paradigm of portable,
zero-dependency artifacts. It precludes the ability to easily share the graph with stakeholders or view it in offline,
air-gapped environments.

## **2\. Perfection Loop Analysis**

To design a superior alternative for the Savant Code ecosystem, the concept of codebase knowledge graphs must be
subjected to a rigorous evaluation framework: RED (Vulnerability Identification), GREEN (Solution Ideation), AUDIT
(Validation), and SELF-CORRECT (Refinement).

### **2.1 RED Phase: Vulnerability Identification**

The evaluation uncovers several critical vulnerabilities in the existing paradigm that must be eradicated in the Savant
implementation.
The primary vulnerability is the LLM-in-the-Loop anti-pattern. Using probabilistic language models to traverse
directories, parse abstract syntax trees, or resolve explicit import paths is a gross misallocation of compute. These
are deterministic, mathematical problems. Attempting to resolve a function call across files via LLM inference
introduces severe hallucination risks and massive token waste12.
The secondary vulnerability is State Desynchronization. If the knowledge graph is not updated synchronously with every
file save or commit, the AI agent operates on a fractured reality. Understand-Anything's heavy LLM reliance makes
continuous synchronization unfeasible, meaning the tool is inherently fighting against the rapid velocity of modern
software development14.
The tertiary vulnerability is monolithic context loading. Extracting data from the knowledge-graph.json via standard
terminal grep commands7 is primitive. It forces the agent to read raw JSON arrays rather than utilizing optimized,
semantic graph queries, leading to immediate context window pollution and degraded model performance.

### **2.2 GREEN Phase: Solution Ideation**

To resolve the vulnerabilities identified, the Savant Code implementation must pivot to a zero-cost, local-first
structural parsing engine, entirely decoupling the mechanical mapping of code from semantic interpretation.
The entire structural graph (files, classes, functions, imports, calls) must be generated locally using Tree-sitter.
Tree-sitter is an advanced, incremental parsing library that produces a Concrete Syntax Tree (CST) and operates locally
on the host machine with zero API token cost15. It utilizes a Generalized LR (GLR) parsing algorithm capable of handling
syntactic ambiguity without requiring code execution, making it the industry standard for editor-integrated code
analysis15.
Instead of writing to a massive, fragile JSON file, the AST and relational data should be persisted in a local SQLite
database, mimicking the robust architecture seen in systems like Engraphis17. This enables sub-millisecond query latency
and allows AI agents to use Model Context Protocol (MCP) tools to query specific "blast radiuses" deterministically,
without loading the whole graph into their context window17.
Language models should only be invoked on-demand to label business domains, write summaries, or generate guided tours.
The structural scaffold must exist completely independently of the language model22.

### **2.3 AUDIT Phase: Validation of Constraints**

The proposed solutions must be audited against Savant Code's strict operating constraints to ensure viability.  
The architecture strictly adheres to the zero-cost mandate. Tree-sitter and SQLite are free, open-source technologies
that run entirely on local compute, eliminating cloud provider API costs for structural parsing15. To address the
semantic tagging costs, the system will leverage local, small-parameter models designed specifically for coding tasks.
Licensing is fully compatible. Tree-sitter operates under the MIT license, SQLite is public domain, and the proposed
visualization library, Cytoscape.js, is MIT-licensed23. This perfectly aligns with Savant Code's Apache 2.0 and MIT
constraints, ensuring the resulting artifact remains unencumbered for enterprise deployment.
The architecture is inherently compatible with the ECHO Protocol. The SQLite queries can be wrapped in MCP tools that
conform to the exact structured JSON schemas required by the ECHO Protocol's message carrier mechanisms24.

### **2.4 SELF-CORRECT Phase: Refinement**

While SQLite solves the agent query problem perfectly, human operators still require visual exploration to understand
architectural domains. The Vite server model utilized by Understand-Anything must be discarded entirely due to its heavy
runtime dependencies.
Instead, visualization will be handled by compiling the SQLite graph data into a single, self-contained HTML file. This
file will bundle the Cytoscape.js rendering engine and Dagre layout algorithms inline, requiring zero external CDN
requests or server processes25. This aligns perfectly with Savant Code's existing /export command, which already focuses
on generating portable, shareable artifacts27.

## **3\. Optimization Plan: Cost, Speed, and Accuracy**

To achieve uncontested superiority over existing tools, the Savant Code Knowledge Graph must implement aggressive
architectural optimizations targeting token expenditure, processing speed, and relational accuracy.

### **3.1 Token Optimization via Deterministic Parsing and Local Models**

The fundamental optimization is the total elimination of cloud LLM token costs for structural mapping. Savant Code will
embed Tree-sitter grammars (supporting over 60 languages natively) to parse codebases17. By leveraging Tree-sitter's
tags.scm query files, the system can instantly capture definitions (@definition.function), references (@reference.call),
and import statements (@import)15. Because this occurs on local compute, building a structural graph of a 2,000-file
repository drops from 30 minutes of expensive API latency to under 10 seconds of local CPU time21.
For semantic tasks—such as labeling the Louvain community clusters with business domain names or summarizing complex
functions—the system will offload processing to local, highly specialized small language models. Specifically,
integrating with Ollama to run the Qwen2.5-Coder series (e.g., the 3B or 7B parameter models) provides state-of-the-art
code reasoning capabilities locally30. The Qwen2.5-Coder models excel at structured outputs and function signature
extraction31, allowing the Savant system to enforce strict JSON schemas for semantic tagging without incurring any cloud
API costs32. This hybrid approach achieves the depth of Understand-Anything at a fraction of the operational cost.

### **3.2 Speed Optimization via Incremental Hashing**

To prevent the graph from suffering silent staleness, it must update continuously as the developer works. A full
repository rebuild on every commit is computationally inefficient and disruptive. Savant Code will implement a highly
optimized incremental synchronization engine.
The system will monitor the active workspace using native file system events. Upon a file modification, an XXH3 or
SHA-256 hash of the file content is generated17. If the hash differs from the record in the SQLite database, only that
specific file is fed into the Tree-sitter engine. Tree-sitter’s native incremental parsing architecture reuses
unaffected nodes from the previous AST, updating only the modified branch15. This differential approach allows massive
projects to update their dependency graphs in a fraction of a second, ensuring the AI agent always possesses real-time,
accurate context without blocking the developer's workflow17.

### **3.3 Accuracy Optimization via Call Resolution Cascade**

A standard AST parse can identify that a function named login() was called, but it struggles to definitively link that
call to the correct definition across a massive monorepo where multiple login() functions might exist. Instead of
relying on an LLM to guess the connection, Savant Code will implement a mathematically rigorous 6-strategy deterministic
resolution cascade to map edges accurately17.

| Resolution Strategy | Confidence Score | Mechanism |
| :---- | :---- | :---- |
| **Import Map** | 0.95 | Traces the callee prefix against the file's explicit import statements to find the exact module path17. |
| **Same Module** | 0.90 | Checks if the function is defined natively within the enclosing file or local namespace17. |
| **Import Map Suffix** | 0.85 | Attempts a suffix-based match against resolved paths if the direct import map fails17. |
| **Unique Name** | 0.75 | Queries the global reverse index; if only one instance of the function name exists globally, it maps the edge automatically17. |
| **Suffix Match** | 0.55 | In cases of identical global names, calculates import-distance scoring to select the nearest logical module17. |

This cascade ensures that the vast majority of cross-file dependencies are mapped flawlessly without a single API call,
isolating the language models entirely from structural reasoning and drastically reducing the hallucination surface
area.

## **4\. Savant Code Integration: Agents and the ECHO Protocol**

Savant Code utilizes a sophisticated multi-agent system, including specialized Scout, Thinker, and Verifier agents,
orchestrated by the ECHO Protocol and a Redis Reasoning Worker33. The Knowledge Graph must not exist as an isolated
utility; rather, it must act as the central nervous system for these autonomous agents.

### **4.1 ECHO Protocol Synergies**

The ECHO Protocol is a finite-state machine (FSM) middleware designed to maintain tone stability, behavioral coherence,
and context management across long-running LLM sessions34. It defines four primary operational states: Sync, Resonance,
Insight, and Calm35. The Knowledge Graph natively enhances these states by providing structured, reliable data streams.
When the agent operates in the **Sync State** (characterized by concise, grounded, and factual responses), it utilizes
MCP tools to query the SQLite graph for exact paths35. If the user asks for the dependencies of a specific service, the
agent retrieves a strict JSON payload via the Echo MCP carrier, guaranteeing factual accuracy without hallucination24.
When transitioning to the **Insight State** (characterized by analytical, high-context reasoning), the agent executes
deeper structural queries35. It can request the Louvain community clusters to understand macro-level domain boundaries
before proposing complex architectural refactors, ensuring the proposed changes align with the system's broader design
patterns6.

### **4.2 Agent Synergies and Blast Radius Computation**

The specialized agents within the Savant ecosystem will interface with the graph deterministically to execute their
unique directives.
**The Scout Agent (Discovery):** Scout is responsible for reconnaissance and orientation. Upon initialization in a new
workspace, Scout triggers the background Tree-sitter parsing engine to build the local SQLite graph. Scout then uses the
resulting community clusters to automatically partition the codebase into logical business domains, saving this
high-level mapping to the Savant Memory Bank (.savant/session.json)33.
**The Thinker Agent (Reasoning & Blast Radius):** The Thinker agent is responsible for planning code modifications. When
tasked with altering a function, Thinker queries the graph to calculate the "blast radius"16. By executing a recursive
query on the calls and imports edges, Thinker traces every dependent module that will be affected by the change. This
prevents the agent from reading thousands of files blindly; instead, it requests only the specific files within the
direct blast radius, maximizing context window efficiency and precision21.
**The Verifier Agent (Validation):** Before generating the final output or committing code, the Verifier agent
crosses-references the proposed diff against the AST graph. If the agent proposes deleting a core interface, the
Verifier queries the SQLite database to ensure no incoming implements or calls edges remain active. This structural
validation at the protocol layer drastically reduces the deployment of hallucinated or broken code37.

## **5\. Feature Specification: The Savant Knowledge Graph**

The Savant Knowledge Graph feature requires a robust, standardized specification to ensure seamless interaction between
the CLI interface, the local SQLite engine, and the Model Context Protocol (MCP) tool surface24.

### **5.1 Relational Data Model**

The internal data model will abandon flat JSON files in favor of an optimized SQLite database (.savant/graph.db),
enabling complex relational queries, recursive path tracing, and transactional safety19.

| Table Name | Schema Definition | Purpose |
| :---- | :---- | :---- |
| **Nodes** | id (PK), type (file, class, function), name, file\_path, start\_line, end\_line, semantic\_summary | Stores the physical and abstract entities discovered in the codebase. The semantic\_summary is populated asynchronously by local models9. |
| **Edges** | source\_id, target\_id, type (imports, calls, implements), confidence\_score | Stores the directed relationships between nodes, including the confidence score derived from the resolution cascade17. |
| **Communities** | cluster\_id, node\_id, domain\_label | Maps individual nodes to macro-level business domains discovered via the Louvain clustering algorithm6. |

### **5.2 Command Line Interface (CLI) Subcommands**

Following best practices for POSIX-compliant, subcommand-based interfaces38, and aligning natively with Savant's
existing architecture (org.savantbuild.runtime.Switches)39, the feature introduces a new graph command suite accessible
via the main binary.

| Command Syntax | Operational Behavior |
| :---- | :---- |
| savant graph build | Triggers a synchronous, deterministic Tree-sitter parse of the entire repository. Bypasses language models entirely, writing structural data directly to SQLite15. |
| savant graph watch | Spawns a background daemon that monitors file system events. Performs incremental XXH3 hashing and differential parsing to keep the graph perpetually synchronized17. |
| savant graph query \--node \<id\> | A diagnostic tool for developers to query the local SQLite database directly from the terminal, returning the blast radius as structured JSON24. |
| savant graph analyze | The semantic processing command. Iterates over the structural communities and utilizes the local Qwen2.5-Coder model to generate business-logic summaries, saving them to the semantic\_summary column30. |

### **5.3 MCP Tool Specifications**

To allow the ECHO Protocol and the autonomous agents to access the graph, the system will expose specific, strictly
typed Model Context Protocol (MCP) tools17. These tools guarantee that agents receive exact data structures rather than
unstructured text.

> 1. get\_blast\_radius(node\_id: string, depth: int): Executes a recursive traversal of the SQLite edge table to return
> 1. an array of file paths that depend on the target node, dictating exactly which files the agent needs to load into
> 1. context16.
> 2. get\_call\_hierarchy(node\_id: string, direction: 'incoming'|'outgoing'): Returns the direct call graph for a
> 2. specific function, aiding in refactoring logic.
> 3. get\_domain\_context(file\_path: string): Returns the semantic summary of the business domain to which the file
> 3. belongs, providing the agent with macro-level intent.

## **6\. Export Integration: The Branded Artifact System**

A critical competitive differentiator for Savant Code is its portable export capabilities. While Understand-Anything
forces users to spin up an active Vite server requiring network access and continuous dependency management3, Savant
Code will generate a zero-dependency, single-file HTML artifact. This artifact can be emailed to stakeholders, embedded
in wiki pages, or viewed completely offline in highly secure, air-gapped environments25.

### **6.1 The Single-File Artifact Architecture**

The export system will utilize Cytoscape.js, a lightweight, highly performant, MIT-licensed graph visualization library,
paired with the Dagre layout engine for optimal hierarchical directed acyclic graph (DAG) routing23.
To achieve true offline capability, the HTML file will contain the Cytoscape.js and Dagre engine minified inline within
\<script\> tags, ensuring absolutely no external Content Delivery Network (CDN) requests are required25. During the
export execution, the SQLite graph data is serialized into a highly compressed JSON object and injected directly into a
JavaScript constant within the HTML document.
The resulting interface will support advanced user experience features including zooming, panning, compound nodes
(visually nesting functions inside classes, and classes inside files), and a robust search bar to filter nodes by
architectural name or semantic domain25. The interface will automatically adapt to the user's system theme, matching
Savant's professional branding.

### **6.2 Seamless CLI Integration**

The export feature extends the existing session export functionality already present in the Savant ecosystem27.  
By executing savant \--export-graph \[output\_path\], the system reads .savant/graph.db, queries the necessary node and
edge structures, renders the HTML template, injects the JavaScript libraries and data payload, and outputs a
self-contained savant-knowledge-graph.html file to the requested directory27.
Furthermore, this integrates deeply with the interactive terminal. When a user executes the /export command within an
active agent session, the interactive prompt will present an option to export either the conversational chat log (the
current behavior) or the architectural knowledge graph, centralizing all export functionality under a unified command
structure40. Support for automated exports, akin to the proposed claude \--export-on-exit flag, will ensure graphs are
automatically preserved at the termination of high-intensity refactoring sessions27.

### **8.1 Distinctive Market Differentiators**

The proposed implementation fundamentally redefines the economics and efficiency of codebase comprehension.  
Compared to Understand-Anything, Savant Code eliminates the catastrophic token burn that currently plagues enterprise
users12. By transitioning structural analysis entirely away from probabilistic LLM reasoning to deterministic
Tree-sitter parsing15, Savant Code achieves mathematically perfect accuracy with zero token expenditure. The utilization
of local Qwen2.5-Coder models for semantic tagging ensures that even the highest-level architectural reasoning remains
entirely free and private30. Furthermore, replacing a brittle, dependency-heavy Vite server with a highly portable,
offline-capable HTML artifact dramatically improves sharability and compliance with stringent corporate security
policies3.
Compared to Engraphis, which offers an excellent, local-first AST graph via SQLite19, Savant's advantage lies in its
profound native integration. Engraphis acts as a standalone memory tool that generic agents must be configured to
interact with. The Savant Knowledge Graph is not an external dependency; it is the core navigational engine explicitly
designed to feed the proprietary Scout, Thinker, and Verifier agents directly through the ECHO Protocol's stateful
middleware24. This native synergy allows Savant to maintain unparalleled tone stability, drastically reduce context
window pollution via precise blast radius targeting, and prevent hallucinated file edits by structurally validating
every proposed change at the protocol layer prior to execution.
The integration of this deterministic, SQLite-backed codebase knowledge graph elevates Savant Code from a generic
conversational agent to a structurally aware architectural assistant. By completely decoupling the mechanical mapping of
code from the costly invocation of language models, the system preserves computational resources exclusively for
high-level reasoning. Paired with a portable visualization system and strict adherence to the ECHO Protocol, this
implementation provides a robust, zero-cost, and offline-capable solution that vastly outperforms all existing market
alternatives.
