# **Root-Cause Analysis and Remediation of OpenTUI Sidebar Row-Highlight Anomalies**

## **1\. OpenTUI Rendering Architecture and Pointer Event Propagation**

To understand the persistent row-highlight anomaly within the Savant-Code CLI sidebar, one must fundamentally
examine the architectural convergence of the OpenTUI layout engine, the React reconciler, and the native terminal
pointer event pipeline. OpenTUI operates by translating declarative component trees into a flat, double-buffered
cell array, known as the FrameBuffer or TextBufferView, utilizing a native Zig core for alpha blending, true color
rendering, and terminal cell compositing1. Within this environment, visual layout is computed using Yoga, a
cross-platform flexbox engine that maps CSS-like spatial properties onto a rigid 2D terminal character grid.
When a user interacts with the terminal via a mouse click, the terminal emulator captures the interaction and
translates it into standard escape sequences, typically following the SGR 1006 protocol for extended mouse
tracking. The OpenTUI native core intercepts these sequences and decodes the exact column and row coordinates. This
raw hardware event is then passed across the foreign function interface (FFI) into the TypeScript runtime, where it
is instantiated as a synthetic MouseDown event2. The framework then initiates a hit-testing phase against the
Yoga-calculated bounding boxes of the currently mounted Renderable nodes.
Hit-testing in OpenTUI operates recursively from the root CliRenderer down to the deepest intersecting child node.
Once the deepest node is identified, the event is dispatched to that specific Renderable via the processMouseEvent
lifecycle method2. At this exact juncture, OpenTUI implements an event-bubbling architecture mirroring the standard
Web DOM specification. If the target node possesses an event handler that consumes the event—specifically by
invoking event.stopPropagation()—the propagation halts immediately3. If the target node does not handle the event,
or if it lacks an explicit event sink, the event systematically bubbles up the ancestral chain, testing each parent
container for a corresponding handler.
If a MouseDown event traverses the entire ancestral chain and reaches the root CliRenderer without being
intercepted or having its default action prevented, the global event orchestrator assumes the interaction was
directed at the underlying text buffer rather than a distinct interactive component. Consequently, the renderer
activates the global selection engine, initiating a drag-to-highlight state originating from the clicked cell
coordinates5. It is this precise fallback mechanism that generates the unintended visual highlighting observed in
the application.

## **2\. Root Cause Analysis**

The root cause of the sidebar row-highlight bug is an event propagation leak stemming from a structural
misalignment between the Yoga flexbox layout and the localized event handlers within the React component tree. The
recent refactoring of the right sidebar from static ASCII box drawing to native OpenTUI flexbox components
inadvertently exposed layout-synthesized whitespace to the global selection engine.
An analysis of the RightSidebar.tsx source code reveals that the root container allocates a strict, fixed-width
layout constraint using width={40} and flexDirection="column". This forces the Yoga engine to explicitly reserve a
40-character wide column on the right side of the terminal display. Nested within this container are multiple
SidebarSection primitives, which in turn encapsulate interactive elements such as FidCard.
The critical flaw was introduced during the optimization of the SidebarSection component's hit area. The
onMouseDown handler, responsible for toggling the expanded state of the section, was applied to an inner \<box\>
component configured with alignSelf="flex-start". The alignSelf="flex-start" property instructs the Yoga engine to
shrink the bounding box of that specific container to match the exact dimensions of its inner content—in this case,
the toggle chevron text and the section title text.
While this correctly restricts the interactive toggle hitbox to the visible text, it leaves the remainder of the
40-character width completely devoid of event listeners. The parent \<box flexDirection="column"\> surrounding the
toggle row fills the remaining horizontal space with empty cells generated by the layout engine. When a user clicks
in this empty space to the right of a sidebar title, the SGR 1006 sequence triggers a MouseDown event targeting the
parent column box. Because this parent box has no onMouseDown handler to invoke stopPropagation(), the event freely
bubbles out of the SidebarSection, out of the RightSidebar, and straight to the root CliRenderer. The root renderer
intercepts the unhandled click, activates the global selection mechanism, and applies the high-contrast selection
background styling to the empty cells, creating the visual symptom of an entire row becoming highlighted6.

## **3\. The Failure of selectable and focusable Properties**

The exhaustive application of selectable={false} and focusable={false} to every \<box\> and \<text\> element in the
sidebar failed to resolve the issue because these properties govern entirely disparate subsystems within the
OpenTUI architecture, neither of which interact with pointer event bubbling.
The OpenTUI architecture strictly separates keyboard navigation scoping from pointer event sinks. The focusable
property is tightly coupled to the FocusScopeRenderable lifecycle3. When focusable is enabled on a component, the
framework registers that node within the internal focus graph, allowing it to participate in sequential Tab and
Shift+Tab traversal, and enabling it to capture keyboard events via processKeyEvent4. Setting focusable={false}
successfully removes the sidebar components from the tab-index array and prevents the rendering of visual focus
indicators, but it exercises absolutely zero authority over the processMouseEvent pipeline. The pointer event
system remains entirely oblivious to the focusable state of a container.
Similarly, the selectable property dictates localized text extraction boundaries, not event propagation. When an
element such as an ASCIIFontRenderable or TextNodeRenderable is marked with selectable={false}, the local component
state instructs the renderer to reject targeted text-copy operations directly against that specific node5. However,
the empty flexbox space triggering the bug is not a text node; it is structurally empty padding synthesized by the
layout algorithm. When the unhandled click reaches the root, the global selection engine operates on the composited
FrameBuffer cell array1. The global selection algorithm scans the raw cells, identifies them as empty buffer space,
and highlights them indiscriminately. Because the event bypassed the component boundaries due to the lack of a
propagation stop, the local selectable={false} flags on adjacent text nodes are never evaluated by the selection
engine. The framework essentially treats the empty sidebar space identically to empty whitespace at the end of a
standard text editor line.

## **4\. Comparable Implementations and Ecosystem Patterns**

An examination of mature OpenTUI-based applications, specifically the opencode-ai/opencode repository and
established UI primitive libraries, demonstrates standard patterns for managing event boundaries in layered or
constrained layouts. The terminal environment lacks a traditional \<body\> element to implicitly absorb stray
clicks, necessitating explicit event sinks when defining boundaries that should not trigger global text selection.
In implementations of floating menus, such as the OpenTUI Dropdown component, the architecture explicitly manages
both click-inside and click-outside detections to prevent event leakage7. The Dropdown primitive binds onMouseDown
handlers directly to its root floating container, ensuring that any click falling within its bounding box is
captured, processed, and destroyed via stopPropagation(). This pattern prevents clicks intended for the dropdown
background from bleeding through to the underlying syntax-highlighted code editor, which would otherwise trigger
unintended text selections or cursor movements.
Furthermore, within the primary layout grids of complex TUI applications, modal overlays and persistent sidebars
consistently implement boundary sinks. When applications implement multi-view dashboards or split-pane interfaces
(such as a CLI render mode with an interactive TUI at the bottom and a scrollback stream at the top), the boundary
containers wrapping interactive widgets enforce strict event containment8. In the specific case of the Savant-Code
CLI sidebar, the absence of an event sink at the RightSidebar container boundary represents a deviation from these
established patterns, allowing the localized structural layout optimization (flex-start) to inadvertently
compromise the global state machine.

## **5\. Failure Modes and Edge Cases Assessment**

When diagnosing unintended visual highlighting in a terminal user interface, it is imperative to distinguish
between application-level rendering artifacts and hardware-level terminal emulator interventions. Terminal
emulators such as iTerm2, Kitty, or Alacritty maintain their own selection buffers (such as the Linux PRIMARY
selection or standard clipboard)9. Users can typically bypass the application's internal mouse protocol by holding
a modifier key (e.g., Shift or Option) while dragging the mouse. This action temporarily suspends the application's
receipt of SGR 1006 sequences, allowing the emulator to directly highlight the rendered text characters on the
screen.
If the row highlight in the sidebar were caused by a terminal emulator override, the visual styling of the
highlight would match the native operating system or terminal theme, and the application's internal state would
remain completely unaware of the interaction. However, the reported anomaly consistently utilizes the high-contrast
selection colors native to OpenTUI's Selection class6, confirming that the phenomenon is driven by the internal
React reconciler and Zig core.
A secondary failure mode involves the potential for typeId indexing errors during rapid layout thrashing. When
OpenTUI elements are frequently attached and detached, edge cases have been documented where internal renderable
IDs desynchronize, causing pointer events to map to stale or destroyed parent nodes10. While defensive checks exist
in the reconciler to safely ignore operations targeting destroyed parents, a click registering against a stale
bounding box could theoretically misroute the event. However, the deterministic reproducibility of this sidebar
bug—occurring consistently on static, fully mounted empty space—rules out transient reconciliation races and
solidifies the diagnosis of a permanent event propagation leak.

## **6\. Alternative Fixes and Tradeoff Analysis**

Several strategies exist for remediating the event propagation leak, each carrying distinct architectural and
user-experience implications for the application.

| Remediation Strategy | Implementation Mechanics | Architectural Tradeoffs | Risk Assessment |
| :---- | :---- | :---- | :---- |
| **Root Boundary Event Sink** (Recommended) | Bind a generic onMouseDown handler to the outermost \<box\> in RightSidebar.tsx that explicitly invokes event.stopPropagation() and event.preventDefault(). | Enforces strict encapsulation. Safely isolates the entire sidebar from the global selection engine while preserving the optimized flex-start toggle hitboxes of child components. | **Negligible Risk.** Standard pattern for UI boundary enforcement. Does not interfere with interactions in the primary chat viewport. |
| **Reverting to Full-Width Handlers** | Remove the alignSelf="flex-start" property from the inner \<box\> of all sidebar primitives, returning the onMouseDown trigger to the full 40-character layout block. | Relies on the functional UI handlers to implicitly consume the events. Eliminates the empty space by expanding the interactive zones to fill the layout. | **Moderate UX Risk.** Violates interaction expectations. Clicking empty space far from a text label will unintentionally trigger state changes (e.g., expanding or collapsing an FID card). |
| **Global Selection Deactivation** | Alter the root renderer configuration via createCliRenderer({ useMouse: false }) or disable the root Selection service entirely. | Completely disables OpenTUI's internal handling of mouse interactions, offloading all selection capabilities strictly to the terminal emulator's OS-level fallback. | **Severe Feature Degradation.** Permanently breaks intended application-level interactions, such as drag-to-copy source code blocks within the main chat interface12. |
| **Component-Level Primitive Sinks** | Add individual onMouseDown={(e) \=\> e.stopPropagation()} sinks to the parent \<box flexDirection="column"\> of every primitive (e.g., SidebarSection, FidCard, AgentStack). | Distributes the event stopping logic across multiple reusable components rather than centralizing it at the macro-layout level. | **High Maintenance Overhead.** Requires patching every existing and future primitive to ensure layout space does not leak events, increasing boilerplate and the likelihood of regressions. |

## **7\. Recommended Implementation**

The most robust and minimally invasive solution is the implementation of a boundary event sink at the root of the
RightSidebar component. This directly addresses the propagation leak without altering the visual layout, degrading
the precision of the inner hitboxes, or interfering with global behaviors outside the sidebar container.
The required modification entails injecting an onMouseDown property into the outermost \<box\> element returned by
the RightSidebar functional component. This handler will intercept any bubbling pointer event that was not consumed
by a specific UI element (such as a toggle or a button) and cleanly terminate its propagation lifecycle.

  const theme \= useTheme()  
  const devMode \= useChatStore((s) \=\> s.devMode)  
  const { fids: activeFids } \= useFids()  
  const displayModel \= IS\_SAVANT\_FREE  
    ? useSavantFreeModelStore.getState().selectedModel  
    : loadSavantCodeModelPreference() ?? model  
  const fids \= activeFids

  return (  
    \<box  
      flexDirection="column"  
      width={40}  
      flexShrink={0}  
      paddingTop={1}  
      paddingBottom={1}  
      paddingLeft={1}  
      paddingRight={1}  
      gap={1}  
      focusable={false}  
      selectable={false}  
      // Binds a propagation sink to the sidebar boundary.  
      // This intercepts all clicks originating in layout-generated empty space  
      // and destroys them before they reach the global Selection engine.  
      onMouseDown={(e: any) \=\> {  
        if (e && typeof e.stopPropagation \=== 'function') {  
          e.stopPropagation()  
        }  
      }}  
    \>  
      \<box  
        flexDirection="column"  
        alignItems="center"  
        gap={1}  
        paddingBottom={1}  
        focusable={false}  
        selectable={false}  
      \>  
        \<text attributes={TextAttributes.BOLD} fg={theme.primary} selectable={false}\>  
          SAVANT  
        \</text\>  
        \<text fg={theme.muted} selectable={false}\>One Mind. A Thousand Faces.\</text\>  
      \</box\>  
        
      {/\* Remainder of the component hierarchy remains unchanged \*/}

By placing the sink on the 40-character wide parent container, any click landing to the right of the SidebarSection
toggle buttons will immediately strike the parent padding/gap space, bubble up exactly one tier to the RightSidebar
boundary, and be safely absorbed.
